# 美术后续建议：突破 22px 的表现力天花板

> 这份文件是给接手的人 / AI（例如 Claude）看的建议书，可以独立阅读。
> 前置背景见 `HANDOFF.md`；美术管线见 `art/README.md`。
>
> **状态更新（已完成）**：下面第 2 节的 **A（表现层改造）和 C 的一部分已经做完了**——
> 机体精灵不再被塞进一格，改成「比格子大、底部对齐、按行序互相遮挡」，
> 占位改为地面环 + 投影，常驻网格线去掉，加了统一光照、外描边和 SD 比例。
> 所以**第 2 节现在主要是历史记录**；真正还没做的第 1 优先事项变成了**地形**（见第 5 节）。
> 剩下没做的是「地图缩放档位」，见 2.A。

## 1. 现状：格子太小，是美术的根本限制

游戏里一个格子是 `TS = 22` 逻辑像素（`src/artifact-fragment.html` 的常量区）。
每个关卡开始时按「铺满地图栏宽度」自动算缩放：

```js
// startLevel() 里
setMapSize(LV.w, LV.h, Math.max(1, Math.min(1.7, (wrap.clientWidth - 4) / (LV.w * TS))));
```

所以实际显示尺寸是 `22 × SC`，而 `SC` 被夹在 **1 ～ 1.7** 之间：

| 关卡 | 地图宽 | 显示尺寸 `22×SC` |
|---|---|---|
| 教学 1/2/3（20–26 宽） | 窄 | 顶到 1.7 → **约 37px** |
| 大规模防卫战（40 宽） | 宽 | 约 22–25px |
| 自由对战（40×40） | 宽 | `SC = 1` → **正好 22px** |

实测：**22px 下，细于约 1px 的线只会变成一团糊**。

**已经采取的对策**（不用再重做）：

1. **机体精灵脱离格子**：`SPR_MUL = {1: 1.55, 2: 1.3, 3: 1.2}`，
   1×1 的机体画成约 1.55 格宽、1.67 格高，底部对齐格子下沿，按脚印下沿排序做画家算法遮挡。
   —— 这一条把可用的绘制面积放大了约 **2.6 倍**，是收益最大的一步。
2. **细节等级 LOD**：按实际显示尺寸自动选 `s`（≤26px，丢细节 + 描边加粗 1.5 倍）/ `m` / `l`。
3. **外描边**：剪影 8 方向偏移垫底，重叠时也分得开。
4. **统一光照 + SD 比例**：统一光轴的硬边赛璐璐明暗；大头（×1.45）、发光眼睛、粗四肢（×1.14）。

## 2. 还可以做的（按性价比排序）

### A. 加地图缩放档位（**仍推荐，唯一没做的表现层项**）

在自动 `SC` 的基础上乘一个玩家可选的倍率（例如 ×1 / ×1.5 / ×2 / ×3），
地图超出视口时滚动。顶栏加一个「缩放」下拉即可。

为什么值得做：

- 现在 `SC` 是「铺满宽度」，**横向空间已经用尽了**——单纯把 `TS` 调大不会让格子变大，
  因为 `SC` 会自动缩小来补偿。真正卡住的是 **1.7 这个上限**，不是 `TS`。
- 滚动基础设施已经有了：`focusOn()` 里已经在用 `wrap.scrollTo(...)`，选中机体时会自动跟随。
- **矢量素材放大不糊**：图标是矢量几何，`spriteCache` 里每种组合只渲染一次，
  把 `SPR_RES`（每格离屏像素，现在 88）按最大倍率调大即可，不需要重画任何素材。
  这是当初选矢量而不是位图的主要好处。

改动点：
- `setMapSize()` / `startLevel()`：把算出来的 `sc` 乘上用户倍率；加一个 `#btnZoom` 之类的控件；
- `unitSprite()` 的 `SPR_RES` 按最大倍率调大（×3 时提到约 200）；
- 注意 `setMapSize` 会 `cv.width = MW*TS*dpr*SC`，×3 倍率下画布像素数涨 9 倍，
  40×40 地图会比较吃内存，建议只对小地图放开高倍率，或按视口裁剪绘制；
- **标记尺寸要跟着缩放**：`drawUnitStatus()` 里的 HP 条、朝向三角、飞行角标用的都是固定像素，
  放大后会显得「机体很大、标记很小」。它们目前基于 `TS`，跟着 `SC` 缩放即可。

### B. 提高 `SC` 上限（一行改动，立刻见效但有限）

把 `Math.min(1.7, ...)` 的上限提到 2.5～3。

- 对**窄地图**有效：教学 3 是 20 宽，理论 `SC` 是 `(栏宽-4)/440`，很容易到 2.2，
  现在被压到 1.7，放开后立刻变成约 50px。
- 对**宽地图无效**：40 宽的地图 `SC` 本来就小于上限，调高没影响。

### C. 侧栏加「选中机体大图」（仍然推荐，便宜）

`unitCardHTML()` 里可以再画一张 96–128px 的机体图标大图
（`MechIcons.makeSprite(id, {...}, 128)`，不传 `lod` 就是完整细节版）。

好处：玩家点开机体的那一刻能看到素材的全部细节，地图只负责「一眼认出是谁」。

## 3. 怎么验证（不需要浏览器也能看到画面）

```powershell
node tools/build-src.mjs      # 改完代码必跑：注入素材 + 同步两份 HTML
node tools/check-art.mjs      # 语法 / 接入点 / 素材全组合渲染 / 外描边
node tools/boot-smoke.mjs     # 启动冒烟：5 个关卡真的跑起来
node tools/render-art.mjs     # 图标对照表 → art/out/
node tools/render-game.mjs    # ★ 用游戏自己的 draw() 渲染真实画面 → art/out/game-*.png
node tools/zoom-png.mjs art/out/game-defense.png 280 460 240 200 4
```

`render-game.mjs` 是关键：沙箱里 headless 浏览器起不来，它用
`tools/lib/canvas2d.mjs`（自己写的 Canvas 2D）顶替浏览器，
所以**即使没有浏览器也能看到真实画面**。已知差异：canvas 文字不渲染（网格坐标、
浮动伤害、撤离区标签）、虚线按实线画、HTML/CSS 界面不在范围内。

两点提醒：

1. **两份 HTML 的同步**：只改 `src/artifact-fragment.html`，然后跑 `build-src.mjs` 自动同步到
   `src/index.html`。`tools/diff-src.mjs` 可以检查一致性。
2. `boot-smoke.mjs` 只能抓「运行时报错」，**抓不到画得好不好看**。

## 4. 画风的天花板（诚实说）

代码矢量路线能做到「整洁、统一、可读」，**到不了**《SD 高达 G 世纪》那种手绘 / 3D 渲染质感。
那套精灵是万代南梦宫用 3D 模型渲染成 2D 的（所以角度、光照、比例天然统一，还能出多方向和多帧）。
要往那个方向走，只有两条路：

| 路线 | 做法 | 一致性 | 成本 |
|---|---|---|---|
| Blender 3D → 2D 精灵 | 建 SD 机体模型，卡通着色 + 描边，固定正交相机（俯角 35–45°）+ 主光 + 轮廓光，渲 512px 带透明通道，再缩放 | 极好（本来就是同一条路） | 要学硬表面建模；23 台可共用零件拼 |
| 委托画师 | 给规格书：角度、光照方向、输出尺寸、透明底、朝向处理 | 好（靠规格书约束） | 需要预算 |

**如果决定走这两条路，现在的表现层已经准备好了**：只要把 `drawUnitSprite()` 里的
`ctx.drawImage(精灵)` 换成读 PNG 精灵即可，其余的（缩放、排序、地面环、状态标记）都不用改。

## 5. 美术下一批的候选清单

| 顺序 | 内容 | 现状 | 备注 |
|---|---|---|---|
| 1 | **地形** | `buildTerrain()` 用程序化色块画（平原/森林/山地/水域/裂谷） | **现在最弱的一环**：平坦纯色 + 生硬的方格边界。地形占画面绝大部分面积，性价比最高 |
| 2 | **战斗特效** | `FX` 系统画线和圆 | 光束、实弹曳光、抛物线、斩击、爆炸、屏障。可沿用同一套矢量管线 |
| 3 | **势力徽章与 UI 皮肤** | 徽章是「势力配色圆环 + 姓名首字」；UI 是裸 CSS | |
| 4 | **标题 / 关卡选择 / 结局界面** | 无 | |
| 5 | **角色头像** | `图片库/` 里有 9 张图，但都是**有版权的作品图** | 需要作者先定版权口径 |
| 6 | 地图缩放档位（2.A）+ 侧栏大图（2.C） | 无 | 一次性把已有素材的表现力再释放一轮 |

地形可以怎么做（不需要新素材，纯代码）：
每格色调扰动（避免大片纯色）、地形边界柔化（用两层错位的边缘而不是硬方格）、
成簇的树与岩石（大小/旋转随机）、裂谷的深度渐变 + 岩壁高光、水岸高光与深浅分层、
大尺度的明暗变化（让整张地图不是均匀一片）。

素材管线是通用的：`art/mech-icons.js` 的坐标系、图元、LOD、光照、外描边、Canvas 后端
都可以直接复用，新增素材只需要在 `BUILD` 表里加条目（或另开一个同结构的模块）。
