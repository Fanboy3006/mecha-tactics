# 美术交接（统筹 → 美术对话，2026-10-08，v0.40.5）

给新开的「美术」对话的入门包。开工顺序：先读这份，再读《任务板》《分工与派活指南》（第 1.5 节分工、第 1.6 节省用量）。技术细节在仓库的 `art/README.md`（素材管线）和 `Claude hand off/docs/美术后续建议.md`（表现层建议）。

## 一、背景
- 美术原来由 DSH（作者本地的另一个 agent）做。作者 10-08 说「DSH 的成果非常不满意」，美术和音频一起转给 Claude 的对话。统筹对话先接了一下（补给箱图标、前线中继），现在作者决定单独开一条美术对话。
- 现在的阶段：规则刚通过第一轮试玩，作者在玩**规则试玩场**和**战术挑战**（手工小关）；肉鸽暂停。美术的目标是**让这些关玩起来更好认、更好看**，不是批量补图。

## 三、现状
- **地图图标**：原创矢量（代码画的 SD 比例机甲），23 个专属图标 + 补给箱；其余 25 台我方、16 种敌方借用同职业原型剪影，按势力配色（见 `图标待办.md`、`node tools/roster.mjs`）。大众脸 G1–G6 用「演习」势力，现在落到天人的绿色调色板（`FACTION_PAL` 没登记）。
- **识别规则**（`art/README.md` 第 5 节）：脚下地面环形状分敌我（方 / 圆），剪影分职业，胸口核心颜色分职业。这套规则是规则对话和作者认可过的，改之前先和作者确认。
- **地形**：纯色块 + 简单纹理（`buildTerrain`），绝壁、重力深渊（v0.34）还没有像样的贴图。
- **表现层限制**：格子 22px，地图有缩放倍率 `SC`（最大 1.7）。`美术后续建议.md` 推荐过：地图缩放档位、侧栏选中机体大图。
- **作者说过的**：DSH 的成果不满意（没说具体哪里，**第一件事是问清楚**）；`图片库/` 里的作品截图是版权素材，**不进游戏**；借用的角色名公开发布前要换。

## 四、建议的第一批（按顺序，作者可以改）
1. **问清方向**：请作者说说对现在画面哪里不满意（图标？地形？特效？整体风格？），有没有喜欢的参考（可以描述，或者给参考图——参考图只用来理解风格，不进游戏、不临摹）。

3. 方向定了再动手：先地形（玩家每一眼都在看），再我方常用机体（大众脸 G1–G6、迪奥这些作者正在玩的），最后补专属图标。

## 五、工作流
1. 改 `art/mech-icons.js` 或 `20-绘制.js` 里归你的函数 → `node tools/build-src.mjs`（素材会自动注入游戏）；
2. 自检：`node tools/check-art.mjs`；看真实画面：`node tools/render-game.mjs`（输出 `art/out/game-*.png`，用 Read 看图）；浏览器测试 `cd "Claude hand off/tests"; NODE_PATH=/opt/npm-tools/node_modules node rule_stages.js`（会截图）；
3. 提交前 `git pull --rebase origin main`；版本号 +0.0.1（`31b-游玩记录与开场菜单.js` 的 `GAME_VERSION`）；提交、推送；
4. 游戏试玩页：`node tools/build-artifact.mjs`，发布 `Claude hand off/dist/artifact/index.html` + `files`（art.js、game.js）到 `https://claude.ai/artifact/DCAtoqhJA8mxFMpvzp8vgc`，**不传 capabilities**；第一次发布前先 `read`；
5. 在《任务板》「美术对话」一栏改状态，和代码一起提交；项目文档用 `project_write` 同步。
