- 音频原来由 DSH 做：8 首曲子 + 9 个音效，全部是代码现场合成（Web Audio），乐谱在 `audio/score.js`。

- 现在：游戏里**没有打包音频**（`tools/build-src.mjs` 的 `AUDIO_ON = false`），声音按钮自动隐藏。`audio/` 源文件都还在。
- 阶段：规则刚通过第一轮试玩，作者在玩规则试玩场和战术挑战；肉鸽暂停。音乐不急，但作者想要有对话专门想这件事。

## 三、要先想清楚的问题（建议的第一件事）
作者没有否定「要有音乐」，否定的是 DSH 现在这套。可选路线（请和作者一起定，不要先埋头写曲子）：
1. **本地曲目加载**：游戏里加一个「选择本地音乐」——作者从自己电脑选文件，按场景（标题 / 我方回合 / 敌方回合 / Boss / 胜利 / 失败）分配，只存在作者浏览器里，**不进仓库、不上传**。这正好对上「我自己试玩时用版权音乐」，也最快见效。
2. **免版税 / CC0 素材**：找授权清楚的曲子和音效，进仓库要记来源和授权。
3. **继续代码合成，但换路线**：`audio/README.md` 里 DSH 自己也承认合成器音色上限低（「16 位游戏机味道」）。可以只保留**音效**用合成（短促、好控制），音乐走 1 或 2。
4. **乐谱 + 作者自己用 DAW 渲染**：`score.js` 能导出 MIDI，作者用真实音源出音频。

- 版权：风格不受保护，具体旋律受保护；**不允许把已有歌曲的旋律抄进 `score.js`**；版权音乐只在作者本地用。
- Claude 听不见：只能验证音高、节奏、电平这些客观项（`audio/README.md`「一句话立场」），好不好听只能作者判断。所以每一步都要尽快给作者能听的东西（试听页 `audio/preview.html` 或游戏里）。

## 四、工作流
1. 改 `audio/` → 需要进游戏时，和作者确认后把 `AUDIO_ON` 改成 true → `node tools/build-src.mjs`；
2. 自检：`node tools/check-audio.mjs`；浏览器测试 `cd "Claude hand off/tests"; NODE_PATH=/opt/npm-tools/node_modules node audio_cues.js`（音频关着时它只检查按钮已隐藏）；
3. 提交前 `git pull --rebase origin main`；版本号 +0.0.1（`31b-游玩记录与开场菜单.js` 的 `GAME_VERSION`）；提交、推送；
4. 游戏试玩页：`node tools/build-artifact.mjs`，发布 `Claude hand off/dist/artifact/index.html` + `files` 到 `https://claude.ai/artifact/DCAtoqhJA8mxFMpvzp8vgc`，**不传 capabilities**；第一次发布前先 `read`。音频打开后 `build-artifact.mjs` 要把音频块也拆成单独的 `audio.js`（现在只拆 art 和 game，到时候写需求单给规则，或者自己改并告诉统筹）；
5. 在《任务板》「音乐对话」一栏改状态，和代码一起提交；项目文档用 `project_write` 同步。
