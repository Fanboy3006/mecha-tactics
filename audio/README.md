# 音乐素材工作台

机甲战棋的音乐素材，全部**代码生成、原创、零音频文件依赖**。

---

## 压缩音频怎么处理（不需要 ffmpeg）

这台机器没有 ffmpeg，但 **Windows 自己带一套完整的媒体编解码器**，可以通过 WinRT 的
`Windows.Media.Transcoding.MediaTranscoder` 调用，PowerShell 能加载它。已经实测可用：

```powershell
powershell -File tools/transcode.ps1 -In 你的音乐.mp3 -Out audio/ref/你的音乐.wav
```

实测结果（`demoBattle` 往返）：

| 方向 | 时长差 | 波形相关系数 |
|---|---|---|
| WAV → MP3 → WAV | 0 秒 | 0.9398 |
| WAV → M4A → WAV | 0 秒 | 0.9366 |

相关性不到 1.0 是正常的 —— MP3/AAC 是有损压缩，加上 44.1k↔48k 重采样，
不可能逐位相同。0.94 说明解码链路是正确工作的。

用 `tools/analyze-audio.mjs` 可以自己复核：

```bash
node tools/analyze-audio.mjs 原始.wav --compare 转回来的.wav
```

**踩过的三个坑**（都写在 `transcode.ps1` 注释里了）：

1. `.ps1` 必须是 **UTF-8 with BOM**。PowerShell 5.1 会按系统 ANSI 读脚本，
   没有 BOM 时中文注释变乱码并导致语法错误。
2. PowerShell 5.1 里「`$变量::枚举成员`」写在 `switch` 块内会**静默取到空值**，必须写完整类型名。
3. `TranscodeAsync()` 返回的是 `System.__ComObject`，读不到 `.Status`，也无法强转成
   `IAsyncAction`，所以拿不到完成信号。**但这不代表转码没跑** —— 我因为读状态失败就抛异常
   退出，把转码中途掐死，产出了只有 5 秒的残缺文件（原曲 16.5 秒）。解决办法是
   不管状态对象，直接盯输出文件大小，连续多次不变才算写完。

**覆盖范围**：Windows Media Foundation 支持 mp3 / AAC(m4a) / WMA / WAV。
它通常**不**支持 OGG Vorbis 和 Opus —— 如果你的素材是这两种格式，
我可以再做一个 `tools/decode-to-wav.html`：你在浏览器里拖入文件，
浏览器用 Web Audio 解码后导出一份 WAV 给我（Chrome 和 Edge 都装了，
浏览器支持全部常见格式）。这条路不需要任何沙箱权限。

## 一句话立场

**我听不见。** 这个工作台就是为这个缺陷造的替代品。

做美术素材时我能自己迭代，靠的是 `read_image` —— 我画出 PNG 然后真的看见它，于是发现"这个图标在 22px 下糊成一团"并去改。音频没有对应的能力，我没有任何听觉反馈。所以这里用两样东西顶替耳朵：

1. **把声音画成图**，让我用眼睛看结构、频段、动态。
2. **对合成结果做数值验证**（逐音符的基频检测），把"音高对不对"变成可判定的问题。

这两样都不等于听觉。它们能确认的是**客观正确性**，不能确认的是**好不好听**。

| `tools/analyze-audio.mjs` | WAV 分析器：格式/电平统计、两文件相似度、转码验证 |
| `tools/transcode.ps1` | **用 Windows 自带 Media Foundation 转码**（不需要 ffmpeg） |
| `tools/lib-png.mjs` | 最小 PNG 编码器（Node 自带 zlib，无依赖） |
| `tools/lib-midi.mjs` | 最小 MIDI 写入器 + 读取器（读取器用于往返自检） |

## 播放层（`mech-audio.js`）：一个刻意的两段式设计

音频这边我看不见也听不见，所以播放层拆成两半，把「能判定的部分」单独拎出来：

1. **`flatten(cue)`**：纯函数，把乐谱摊平成 `{第几拍, 声部, 音高, 时值}` 的时间表。
   不需要 `AudioContext`，所以能在 Node 里跑自检 —— 音高、时间、音域、和弦齐不齐全都能验。
2. **`voices`**：把时间表上的一个音符变成 Web Audio 节点（12 个声部各一个函数）。

好处是「音高写错了」「八度写错了」这类 bug 在**跑自检时**就会被抓住，
不用等到有人听了说「哪里怪怪的」。这和美术那边用 `render-art.mjs` 先把图画出来看是同一个套路。

`node tools/check-audio.mjs` 会用一个**假 AudioContext** 把 `play / sfx / setVolume / mute / stop`
整条流程跑一遍，确认不抛异常、节点真的被创建、排程在往前走。

**警告：Web Audio 版本和离线渲染版本音色不完全一样。** 离线版是 `audio-lab.mjs` 里的
polyBLEP 振荡器 + 自定义滤波器；游戏里是用 Web Audio 的原生节点重搭的同一套结构。
结构、音高、节奏一致，**音色细节有差别**。要听「成品音色」听 `audio/out/*.wav`，
要听「音符本身」听 `audio/out/*.mid`。

## 用法

```bash
node tools/audio-lab.mjs                        # 渲染全部曲目并自检
node tools/audio-lab.mjs demoBattle             # 只渲染某一首
node tools/audio-lab.mjs --detail=lead,8,16     # 额外输出某轨某段的"可读音高"放大图
```

产物：

- `demoBattle.wav` —— 我的合成器渲染的成品，游戏里最终听到的就是这个音色路线
- `demoBattle.mid` —— **用你的现成音源听音符本身**（任何 DAW、任何 GM 播放器）
- `demoBattle-spectrum.png` —— 全曲波形 + 对数频谱
- `demoBattle-stems.png` —— 9 个分轨各自的波形 + 频谱
- `demoBattle-detail.png` —— 指定段落的放大频谱（`--detail`）

## 怎么改音乐

**只改 `audio/score.js`**，不要去动 `tools/audio-lab.mjs` 里的任何乐器函数（那些是"音色"，不是"曲子"）。

乐谱用可读的格子写：

```js
/* 16 分音符格子：K 底鼓 S 军鼓 H 闭镲 O 开镲 C 强音镲 . 空 */
drumGrid(tr, 1, 'K...S.K.K...S...');

/* 八分音符贝斯，参数是相对根音的半音偏移 */
bassLine(tr, 2, 'Dm', [0, 0, 0, 0, 12, 0, 7, 12]);

/* 吉他节奏：X 闷音，- 放响 */
gtrGrid(tr, 6, 'Bb', '-.X.X.X.-.X.X.X.');

/* 主旋律：[拍, MIDI 音高, 时值(拍)] */
lead(tr, 2, [[0, 69, 0.5], [0.5, 74, 0.5], [1, 77, 1]]);
```

单位约定（**踩过一次坑，务必注意**）：

- `t` / `d` 的单位是**拍**，不是秒。
- `octave` 的单位是**八度**，不是半音。写 `1` 是高一个八度。
  曾经因为参数名叫 `oct` 语义含糊，把 `12` 当成"高 12 个半音"传进去，结果吉他被推高 12 个八度（约 475kHz，远超奈奎斯特频率，只剩混叠噪声）。现在有音域检查兜底。

## 自检能证明什么、不能证明什么

每次渲染都会跑，全部通过才返回 0。

### 能证明

| 检查 | 抓得住什么 |
|---|---|
| 分轨能量 | 写了事件但乐器没发声（**真抓过一次**：起音包络在 t=0 是 0，而我把"包络为 0"当成退出条件，导致四轨整轨静音） |
| 削顶样本数 | 增益过高导致削顶爆音 |
| 音高验证（单声部） | 合成器把音高渲染错了 |
| 音高验证（和弦） | 乐谱上写的和弦音在频谱里根本不存在（**真抓过一次**：上述 12 个八度的 bug） |
| 乐谱音域检查 | "单位写错"这类荒谬音高 |
| MIDI 往返 | MIDI 文件结构损坏 |
| 频谱图 | 频段拥挤/糊成一团、结构不对、有静音缺口 |

音高验证按内容分三种方法，因为不同内容能验证的东西不一样：

- **单声部**（贝斯、主旋律）→ HPS 谐波积谱估基频，和乐谱严格比对（±0.6 半音）
- **和弦**（吉他、铺底）→ 逐个检查**每个和弦音**在频谱里是否存在（相对峰值 −30dB 以内）。
  单基频检测器没法从整个和弦反推根音，那是方法限制；"和弦音齐不齐"才是该验的。
- **打击乐**（定音鼓）→ **不做音高断言**。原因是物理限制：0.5 拍的音符掐掉首尾后约 0.1 秒，
  0.1 秒窗口对 110Hz 的分辨率约 10Hz，而 110Hz 处一个半音只有 6.5Hz —— 原理上分不出半音。
  与其把标准降到能过，不如明说验不了。

### 不能证明

- **好不好听、够不够燃、有没有记忆点。** 这只能靠耳朵，而我没有。
- **混音平衡好不好。** 频谱图能看出"低频挤在一起"，但"该谁大声"是审美判断。
- **音色对不对。** 合成器音色是不是你要的那种"热血"，我判断不了。
- **弦乐/铜管是否像真乐器。** 我的合成器是纯算法振荡器，不是采样音源。

### 因此：分工

**你出耳朵，我出工程。** 循环是：

```
你说"副歌要更燃" → 我改 score.js（转调/加层/改节奏型/改音区）
→ 我自检客观项 → 你听 MIDI 和 WAV → 你说哪里不对 → 重复
```

## 关于当前这套合成器的音色上限（重要）

现在的音色路线是**算法合成器**：polyBLEP 抗混叠锯齿/方波、状态变量滤波器、tanh 失真、
Schroeder 混响、附点八分延迟。

它**不可能**做出真实录音的质感 —— 机战原声里的电吉他是真人弹的、弦乐是真人拉的、
人声是真人唱的，还有大预算的后期。我做不到，任何代码合成器都做不到。

它**能**做到的，是 16 位游戏机那种"热血动画歌"的味道。而对本作来说这不一定是妥协：

- 这是一个单 HTML 文件、无构建步骤、无依赖、格子只有 22px 的战棋
- 运行时用 Web Audio 现场合成 = **零音频文件、零版权风险、零加载时间**
- 这个体量的游戏配 chiptune/合成器摇滚，风格上是自洽的

如果你要的是"听起来像真实录音的机战歌"，正确的路线不是让我硬撑，而是：
我把 `score.js` 的乐谱写好 → 导出 MIDI → **你在 DAW 里用真实音源渲染**。
乐谱是我的活，音色是你的活。这条路现在就是通的。

## 版权

- **风格不受版权保护。** "热血动画歌""电吉他+管弦""快速定音鼓""转调副歌"都是公有领域的音乐语汇，可以随便用。
- **具体旋律受保护。** 不允许把任何已有歌曲的旋律、riff 或乐句抄进 `score.js`。
- 如果你自己哼了一段旋律想用，把音高写进 `score.js` —— **那一段的著作权是你的**，我只是做编曲、配器、和声、节奏组和混音。
- 目前 `score.js` 里的旋律和和声进行都是为本作原创的（D 小调，i–VI–III–VII）。

## 加一首新曲

在 `score.js` 里照 `buildDemoBattle` 写一个 builder，然后注册进 `CUES`：

```js
const CUES = {
  demoBattle: buildDemoBattle(),
  myNewCue:   buildMyNewCue(),      // 加这里
};
```

游戏侧要用的话，`MechScore` 是用 UMD 导出的（和 `art/mech-icons.js` 一样），
既能被 `require` 加载（离线工具），也会挂到 `globalThis`（浏览器里给游戏用）。
