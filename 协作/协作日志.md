## 2026-10-05 · DSH · v0.27 · aider 装好了（Python 3.13 / 3.14 的坑）+ ds_code 不再把失败报成成功
**起因**：作者照着上一条日志去装 aider，`pip install aider-chat` 直接崩：
`pip._vendor.pyproject_hooks._impl.BackendUnavailable: Cannot import 'setuptools.build_meta'`。

**诊断（问题不在 setuptools）**
- 新版 aider **没有声明支持 Python 3.13 / 3.14**，pip 于是**悄悄退回 2023 年的 `aider-chat 0.16.0`**；
- 那个老版本把依赖死锁成 `numpy==1.24.3`、`scipy==1.10.1`、`tiktoken==0.4.0`、`aiohttp==3.8.4` 等，
  这些版本都**没有 3.13 / 3.14 的 wheel**，pip 只好去**源码编译 numpy**，编译环境一崩就报上面那个错。
- 所以「装 setuptools」是治不好的；换 Python 版本才是正解。

**解决**：用 `uv` + 它自带的 CPython **3.12.15**，装进独立 venv（没动系统里的 3.13 / 3.14）：
`C:\Users\zxwu0\.aider312\Scripts\aider.exe` → **aider 0.86.2**，一路都是 wheel，秒装。

**顺手修了两个自家的问题**
1. `DS_MCP_AIDER_CMD` 原来一律用 `node` 去跑（README 里却写着「指向 aider.exe 全路径」——对不上，是个真 bug）。
   现在按后缀分派：`.exe` 等直接执行、`.mjs`/`.js` 用 node（只有自检的假 aider）、`.cmd`/`.bat` 走 `cmd.exe /c`。
   （自检加了 4 项断言。）**因为默认走 PATH 里的 `aider`，这个 bug 在装好 aider 之前不会暴露。**
2. **实测发现 aider 出错时退出码照样是 0**（key 不对时它打印 `Authentication Fails` 然后 exit 0），
   于是 `ds_code` 会把失败报成「✓ 完成」。现在不信退出码了：自己数一遍「这次到底动没动文件」——
   一个文件都没改、也没新提交 → 明确写 ⚠；输出里有 `Authentication Fails` / `litellm.*Error` / `Traceback` 等字样 → 直接判 `isError`。
   （自检加了 2 项断言。）

**其它**：`.gitignore` 加了 `.aider*`、`.env`、`.env.local`（aider 会在仓库里留聊天记录、标签缓存、输入历史）。
README 第 1 节换成 uv + Python 3.12 的装法并把这个坑写进去；`claude_desktop_config.json` 示例加了 `DS_MCP_AIDER_CMD` 那一行。

**验证**
- `node tools/deepseek-mcp/selftest.mjs`：**36 项全过**，exit=0（在临时目录的假项目上跑，不碰真仓库）。
- **真 aider 接线验证**：故意填一个假 key 跑 `ds_code` —— aider 真的起来了、连上了 DeepSeek、返回
  `Authentication Fails`；`ds_code` 如实报 `isError=true` + ⚠「一个文件都没改」+「aider 输出里有报错」。这条同时证明了接线和报错判定。

**还剩最后一步（只能作者做）**：把真的 `DEEPSEEK_API_KEY` 填进 `%APPDATA%\Claude\claude_desktop_config.json` 的 `env` 段
