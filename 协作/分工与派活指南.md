# 分工与派活指南（2026-10-05 起）

## 1. 谁做什么
| 角色 | 负责 |
|---|---|
| **作者** | 定方向、试玩、反馈（GitHub Issues 或直接说）、拍板设定 |
| **Claude**（claude.ai 桌面版对话） | 规则与数值设计、世界观和角色设定、写需求单、给 DeepSeek 派活、审改动、规则书和项目文档、整理试玩反馈 |
| **DeepSeek**（经 `ds_code` 工具，在作者电脑 `C:\DSH-机战` 里跑 Aider） | 照需求单写代码、跑测试、提交 |
| **DSH**（作者本地的另一个 agent） | 美术、音频、工具脚本；DeepSeek 工具本身出大问题时修它 |

原则：**直接编程交给 DeepSeek；涉及世界观、设定、规则判断的留给 Claude。** 作者只在 Claude 桌面版一个界面里调度。

## 2. 工作流
1. 作者提需求 → Claude 写进 `需求单.md`（做什么 + 验收标准）。
2. Claude 用 `ds_code` 派给 DeepSeek，**一次一件小事**，写清「哪个文件、哪一行、改成什么」。
3. DeepSeek 改完，工具自动：统一 LF → `build-src` → 并入同一提交 → `build-src --check` → 跑指定测试。返回只有提交号、diff 统计、测试结果。
4. Claude 审：看 diff 统计是不是只动了该动的文件、行数对不对；有疑问再拉下来看具体改动、跑测试。
5. 没问题 → `ds_code("/run git push origin main")` 推送；Claude 这边 `git pull`，更新需求单、任务板、规则书。
6. 大版本时 Claude 更新 claude.ai 试玩页面；平时试玩以 GitHub 为准。

## 3. 什么活适合给 DeepSeek
- ✅ 改动范围明确、能写清改哪里的：改数值、加一条断言、在指定位置插入一段给定的代码、按清楚的规格实现一个小功能。
- ✅ 每张需求单拆成几步分别派，每步都能单独验收。
- ⚠ 需要通读大文件、理解整体设计的：Claude 先读、先拆好，再给 DeepSeek 精确指令。
- ❌ 一次塞整个大文件（它装不下 512KB 的 fragment）；涉及世界观 / 剧情设定（项目设定文档**不发给 DeepSeek**）。

## 4. 派活时怎么写
- 只给要改的文件（`files` 参数），源文件在 `Claude hand off/src/js/`，不要给 fragment / index.html（生成物）。
- 写明「只改这一处，别的文件一个都不要碰」。DeepSeek 会自作主张多改，实际出过两次：
  - 删 IIFE 收尾，游戏会整个跑不起来；
  - 往自检脚本里重复写了一段，脚本跑不起来。
- 写明提交信息。能给原样代码就给原样代码。
- 给 `test` 参数跑相关浏览器测试（作者电脑已装 Playwright）。
- 以 `/` 开头的任务是 Aider 命令，用来跑命令行：`/run git push origin main`、`/run git pull --ff-only origin main`。

## 5. 已知坑
| 现象 | 原因 / 处理 |
|---|---|
| 一行改动变成整文件几百行 | 换行符。已加 `--line-endings lf` 和事后统一 LF |
| 提交里 fragment / index.html 没更新 | Aider 只「建议」命令不执行。工具已改成自动跑 `build-src` |
| 单个 js 文件括号不配对被「修」掉 | 已关 Aider 自动 lint，并在每个任务前固定加提醒 |
| Aider 反问问题、不动手 | 任务里写「不要提问，直接改」，并把选择题提前答好 |
| 改了 `tools/deepseek-mcp/` 不生效 | MCP 服务器要**重启 Claude 桌面版**才会重新加载 |
| 测试里用了游戏内部变量，报 `is not defined` | 游戏在 IIFE 里，测试只能用 `window.__game`；需要的就加进 `__game` |
| 返回「aider 退出码 0 但没改动」 | 多半是任务没落实或在反问，看输出尾部 |
