## #1 拆分 fragment（优先，先做这张）
**目的**：`src/artifact-fragment.html` 已经 7700 多行，任何人改一处都要读一大块。拆开后谁改哪块只读哪块。

**做什么**
- 把 fragment 里 `<script>` 的内容按现有分节注释（`/* ---------- 名字 ---------- */`）拆成 `src/js/NN-名字.js`（`NN` 是顺序号）；CSS 拆到 `src/css/`，HTML 骨架留在 `src/shell.html`。
- `tools/build-src.mjs` 增加一步：按文件名顺序拼回 `artifact-fragment.html`，再像现在一样生成 `index.html`。`ART` / `AUDIO` 两段生成物照旧注入。
- 以后**只改 `src/js/` 等源文件**，fragment 和 index.html 都是生成物（在 README 和接口约定里写明）。
- 所有测试脚本照旧读 fragment，不用改。

**验收**
- 拆分后第一次构建出的 fragment 与拆分前**逐字节相同**（`diff` 为空）；
- `build-src --check` 通过；`tests/` 全部脚本无 ✗、`ERRS []`；
- 单个 js 文件尽量不超过 800 行（太大的分节可以再拆）。

## #4 DeepSeek 接进 Claude 桌面版（MCP 服务器）
**目的**：作者只在 Claude 桌面版一个界面里调度。Claude 写需求后直接调用本地工具，让 DeepSeek 去改代码，不用作者在两个窗口之间转述。

**做什么**：`tools/deepseek-mcp/`，一个本地 stdio MCP 服务器（Node，`@modelcontextprotocol/sdk`）：
- 工具 `ds_code({task, files?, test?})`：
  - 在 `C:\DSH-机战` 里调用 Aider（`pip install aider-chat`），`aider --model deepseek/deepseek-chat --yes-always --message <task> <files...>`；Aider 会自己读文件、改文件、git 提交；
  - 跑完自动执行 `node tools/build-src.mjs --check`，如果给了 `test`，再跑那个测试脚本；
  - **返回值要短**（不超过 4000 字）：提交号、`git diff --stat`、测试结果的 ✓ / ✗ 行和 `ERRS` 行。不要把整段代码返回。
- 工具 `ds_status()`：返回 `git log --oneline -5` 和 `git status --short`。
- API key 只放在环境变量 `DEEPSEEK_API_KEY` 里（写在 `claude_desktop_config.json` 的 `env`），**不进仓库**。
- 只允许在 `C:\DSH-机战` 里操作；**不要**把项目里的世界观 / 剧情设定文档发给 DeepSeek（代码仓库本来就公开，没关系）。
- 写一份 `tools/deepseek-mcp/README.md`：安装步骤，以及 `claude_desktop_config.json` 的示例配置段。

**验收**：作者在桌面版里重启后能看到这两个工具；Claude 调 `ds_code` 完成一个小改动（比如 #2），返回里有提交号和测试结果。
